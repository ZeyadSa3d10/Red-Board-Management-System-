# دور الموظف في نظام بناء材料 ERP

## نظرة عامة

يعد دور الموظف (Staff) في نظام بناء材料 ERP مسؤولاً عن العمليات اليومية في الفرع الذي يعمل به. يركز دور الموظف على إدارة المبيعات، المخزون، والمعاملات اليومية للفرع دون الوصول إلى الإعدادات الإدارية الشاملة أو تقارير المالكين والمحاسبين المتقدمة.

## الصلاحيات والوصول

يمكن للموظف الوصول إلى:

1. لوحة تحكم الفرع (Branch Dashboard)
2. إدارة الفواتير (Branch Invoices)
3. مخزون الفرع (Branch Inventory)
4. إيراد اليوم الفرعي (Branch Daily Revenue)
5. إدارة المؤجل (Branch Deferred)
6. التحويلات بين الفروع (Branch Transfers)
7. أوامر التوريد والتركيب (Branch Supply Installation)
8. المرتجعات (Branch Returns)
9. إدارة العملاء (Branch Clients)
10. إدارة المصروفات (Branch Expenses)
11. دفتر الأستاذ العام (Ledger)
12. نقطة البيع (POS Page)

ملاحظة: لا يمكن للموظف الوصول إلى:

- إدارة الموظفين (إضافة/تعديل/حذف الموظفين)
- تقارير المالكين والمحاسبين المتقدمة
- إعدادات الفروع والمنتجات والعملاء والموردين على مستوى النظام
- التقارير المالية الشاملة

## الوصف التفصيلي للصفحات المتاحة للموظف

### 1. لوحة تحكم الفرع (BranchDashboard)

#### الهدف

عرض ملخص يومي لأداء الفرع في نظرة سريعة، بما في ذلك الإيرادات، المصروفات، والمعاملات.

#### المكونات الرئيسية:

- **بطاقات الإحصائيات (StatCards):**
  - إيراد اليوم: صافي الإيراد بعد خصم المرتجعات
  - نقدي: المبلغ المحصل نقداً
  - فودافون كاش: المبلغ المحصل عبر فودافون كاش
  - شيكات: المبلغ المحصل عبر الشيكات
  - تحويل بنكي: المبلغ المحول عبر البنوك
  - المبيعات: إجمالي قيمة المبيعات
  - المرتجعات: إجمالي قيمة المرتجعات
  - عدد الفواتير: عدد الفواتير الصادرة اليوم
  - توريد وتركيب: عدد أوامر التوريد والتركيب
  - الديون المحصلة: المبلغ المحصل من الحسابات الآجلة
  - المصروفات: إجمالي المصروفات اليومية
  - الصافي: صافي الإيراد بعد خصم المصروفات

- **محدد التاريخ والفرع:**
  - اختيار تاريخ لعرض بيانات يوم محدد
  - اختيار فرع (للموظفين الذين يعملون في فروع متعددة أو للمحاسبين/المالكين)

- **جدول المصروفات:**
  - عرض تفصيلي للمصروفات اليومية مع الوصف، المبلغ، والملاحظات

### 2. مخزون الفرع (BranchInventory)

#### الهدف

عرض وإدارة مخزون الفرع الحالي مع إمكانية رؤية مخزون الفروع الأخرى للتحويل أو التحويل.

#### كيف يعمل:

- يستدعي API للحصول على منتجات الفرع (`api.getProductsByBranch(branchId)`)
- يستدعي API للحصول على مخزون جميع الفروع (`api.getAllStock()`)
- يعرض البيانات باستخدام مكون StockTable المتقدم مع تخصيص لفرع الموظف

#### ما يراه الموظف:

- جدول شامل يحتوي على:
  - كود المنتج (الباركود أو المعرف)
  - اسم المنتج
  - الفئة
  - الوحدة
  - المخزون في فرع الموظف
  - المخزون في فروع أخرى (للمراجعة والتحويل المحتمل)
  - المخزون الإجمالي عبر جميع الفروع
  - متوسط التكلفة (إذا كان الصلاحية تسمح)
  - سعر البيع
  - القيمة الإجمالية بالتكلفة أو حسب سعر البيع
  - حالة المخزون (منخفض/متوفر) مع تنبيه بصري
  - ملاحظة: أزرار التعديل والحذف غير متوفرة للموظف العادي (محدودة للمالكين والمحاسبين في بعض السياقات)

### 3. الفواتير (BranchInvoices)

#### الهدف

إنشاء وعرض وإدارة فواتير المبيعات والفرع.

#### المكونات الرئيسية:

- **زر إنشاء فاتورة جديدة:**
  - يفتح نموذج إنشاء فاتورة مبيعات جديدة (SalesInvoiceForm)

- **فلاتر متقدمة:**
  - بحث برقم الفاتورة أو اسم العميل
  - تصفية حسب نوع الفاتورة (بيع نقدي، بيع آجل، مرتجع، توريد وتركيب، إلخ)
  - تصفية حسب التاريخ (من تاريخ، إلى تاريخ)

- **جدول الفواتير:**
  - يعرض قائمة الفواتير مع:
    - رقم الفاتورة
    - التاريخ والوقت
    - نوع الفاتورة (مع شارة ملونة لتحديد النوع)
    - الفرع
    - العميل/المشروع
    - صادر باسم (اسم الموظف الذي أنشأ الفاتورة)
    - الإجمالي (مع تنسيق العملة)
    - طريقة الدفع
    - زر عرض تفاصيل الفاتورة (InvoicePrint)

- **تفاصيل الفاتورة:**
  - عند النقر على فاتورة، يعرض نافذة منبثقة بتفاصيل كاملة للفاتورة
  - يدعم الفواتير العادية وفواتير الشراء من الموردين

### 4. إيراد اليوم الفرعي (BranchDailyRevenue)

#### الهدف

تحليل مفصل لإيرادات ونشاطات الفرع ليوم محدد.

#### المكونات الرئيسية:

- **بطاقات الإحصائيات:**
  - صافي الإيراد: الإيراد الإجمالي بعد خصم المرتجعات
  - إجمالي المبيعات: قيمة جميع المبيعات
  - المرتجعات: قيمة جميع المرتجعات
  - نقدي، فودافون كاش، شيكات، تحويل بنكي: تفاصيل طرق الدفع
  - توريد وتركيب: عدد أوامر التوريد والتركيب
  - الديون المحصلة: المبلغ المحصل من الحسابات الآجلة
  - عدد الفواتير: إجمالي عدد الفواتير
  - المصروفات: إجمالي المصروفات
  - الصافي بعد المصروفات: صافي الربح لليوم

- **ملخص المعاملات:**
  - جدول تفصيلي لجميع المعاملات مع:
    - التسلسل
    - رقم الفاتورة
    - نوع المعاملة
    - طريقة الدفع
    - العميل
    - الإجمالي
    - التاريخ

- **جدول المصروفات:**
  - عرض تفصيلي للمصروفات مع الوصف، المبلغ، والملاحظات

### 5. إدارة المؤجل (BranchDeferred)

#### الهدف

متابعة وإدارة الحسابات الآجلة (ما يدين به العملاء للفرع).

#### المميزات المتوقعة:

- عرض قائمة العملاء مع مبالغهم المستحقة
- تصنيف الديون حسب المدة (حالي، 30 يومًا، 60 يومًا، 90 يومًا، إلخ)
- تسجيل التحصيلات من العملاء
- عرض إحصائيات التحصيل والمبالغ المتبقية

### 6. التحويلات بين الفروع (BranchTransfers)

#### الهدف

تحويل المخزون بين الفروع المختلفة لإدارة المخزون وتلبية الطلب.

#### المميزات المتوقعة:

- إنشاء طلب تحويل مخزون من فرع إلى آخر
- تحديد المنتجات والكميات المراد تحويلها
- متابعة حالة التحويلات (معلق، مكتمل، ملغى)
- إشعار الفرع المستلم بالتحويل الوارد

### 7. أوامر التوريد والتركيب (BranchSupplyInstallation)

#### الهدف

إدارة أوامر العملاء التي تتطلب توريد منتجات وخدمات تركيب.

#### المميزات المتوقعة:

- عرض قائمة أوامر التوريد والتركيب
- إنشاء أوامر جديدة مع تفاصيل المنتج، الكمية، ومتطلبات التركيب
- متابعة حالة الأمر (جديد، قيد التنفيذ، مكتمل، ملغى)
- ربط الأمر بالفاتورة عند الإكمال

### 8. المرتجعات (BranchReturns)

#### الهدف

إدارة مرتجعات المبيعات من العملاء.

#### المميزات المتوقعة:

- عرض قائمة المرتجعات
- إنشاء مرتجع جديد لفاتورة بيع
- تحديد سبب المرتجع وحالة المنتج المرتجع
- استرداد المبلغ للعميل أو إنشاء فاتورة استبدال
- تحديث المخزون عند إرجاع المنتج

### 9. إدارة العملاء (BranchClients)

#### الهدف

إدارة معلومات العملاء المرتبطة بالفرع.

#### المميزات المتوقعة:

- عرض قائمة العملاء مع تفاصيل الاتصال
- إضافة عملاء جدد أو تعديل بيانات العملاء existentes
- عرض تاريخ معاملات العميل (فواتير، مدفوعات، مستحقات)
- تصنيف العملاء حسب النوع أو المنطقة

### 10. إدارة المصروفات (BranchExpenses)

#### الهدف

تسجيل وتتبع مصروفات الفرع اليومية والتشغيلية.

#### المميزات المتوقعة:

- عرض قائمة المصروفات مع الوصف، المبلغ، والتاريخ
- إضافة مصروف جديد مع تصنيف (إيجار، رواتب، فواتير، إلخ)
- تصفية المصروفات حسب التاريخ أو النوع
- تقارير المصروفات الشهرية أو السنوية

### 11. دفتر الأستاذ العام (Ledger)

#### الهدف

عرض سجل محاسبي شامل لجميع المعاملات المالية للفرع.

#### المميزات المتوقعة:

- عرض جميع المعاملات الدائنة والمدينة
- ترحيل تلقائي من الفواتير، المصروفات، والتحويلات
- رصيد حساب متجدد
- تصفية حسب التاريخ، نوع المعاملة، أو الحساب المحاسبي
- تصدير البيانات للمراجعة المحاسبية

### 12. نقطة البيع (PosPage)

#### الهدف

واجهة مبسطة وسريعة لإجراء مبيعات مباشرة عند نقطة البيع.

#### المميزات المتوقعة:

- بحث سريع عن المنتجات بالاسم أو الباركود
- إضافة منتجات إلى سلة الشراء مع تحديد الكمية
- تطبيق الخصومات أو العروض الخاصة
- اختيار طريقة الدفع (نقدي، فودافون كاش، شيك، تحويل بنكي)
- طباعة الفاتورة فور إتمام البيع
- دعم العملاء المسجلين والعملاء النقديين
- تحديث المخزون فور إتمام البيع

## التقنيات المستخدمة في الواجهة الأمامية

- **React مع hooks:** useState, useEffect, useCallback لإدارة الحالة والتأثيرات الجانبية
- **React Context:** useAuth للوصول إلى معلومات المستخدم والصلاحيات
- **React Icons:** для отображения интуитивных иконок (BsCashCoin, BsReceipt, etc.)
- **مكونات مخصصة مُعادة الاستخدام:**
  - StatCard: لعرض الإحصائيات بطاقات جذابة
  - Modal: للنوافذ المنبثقة (إضافة موظف، تفاصيل الفاتورة، إلخ)
  - Badge: لتصنيف الحالات والأنواع بشارات ملونة
  - Spinner: لعرض حالة التحميل
  - EmptyState: لعرض رسالة عند عدم وجود بيانات
  - TableComponents: مكونات الجدول المخصصة (table-custom, td-name, td-qty, إلخ)
  - FilterSystem: نظام تصفية متقدم (FilterBar, FilterGroup, FilterSearch, useFilters hook)
- **أدوات مساعدة (utils):**
  - formatCurrency: لتنسيق العملة الموحد
  - formatDate و formatDateTime: لتنسيق التواريخ والتواريخ والوقت
  - formatRole: لتنسيق عرض دور الموظف
  - getToday: للحصول على تاريخ اليوم بتنسيق مناسب
  - formatInvoiceType, formatPaymentMethod, getInvoiceBadgeColor: لتنسيق عرض الفواتير
- **اتصال بالخادم:**通过 api/realApi.js 进行所有后端通信

## تدفق العمل النموذجي للموظف

1. **بدء الوردية:**
   - تسجيل الدخول إلى النظام
   - زيارة لوحة تحكم الفرع لعرض نظرة عامة على اليوم السابق أو التخطيط لليوم الحالي

2. **خلال الوردية:**
   - استخدام نقطة البيع (POS) للمبيعات المباشرة النقدية
   - إنشاء فواتير مبيعات للعملاء (نقدي أو آجل)
   - مراقبة المخزون عبر صفحة مخزون الفرع
   - تسجيل المصروفات التي تحدث خلال اليوم
   - متابعة المدفوعات الآجلة الواردة عبر صفحة المؤجل
   - معالجة المرتجعات إن وجدت

3. **نهاية الوردية:**
   - مراجعة إيراد اليوم عبر صفحة إيراد اليوم الفرعي
   - التحقق من إغلاق الصندوق وتطابق المبالغ
   - تسجيل أي مصروفات متأخرة
   - إعداد تقرير تسليم للوردة التالية إن لزم الأمر

## القيود والضوابط

رغم أن الموظف لديه وصول واسع لعمليات الفرع اليومية، هناك بعض القيود الهامة:

1. **لا يمكن تعديل الأسعار أو إعدادات المنتجات** - هذه محفوظة للمالكين
2. **لا يمكن إضافة أو تعديل العملاء أو الموردين على مستوى النظام** - قد يكون هناك وصول محدود لإضافة عملاء فرعية
3. **لا يمكن الوصول إلى تقارير الأرباح والخسائر الشاملة** - هذه محفوظة للمحاسبين والمالكين
4. **لا يمكن إدارة الموظفين** - إضافة/تعديل/حذف الموظفين محفوظة للمالكين فقط
5. **لا يمكن تعديل الإعدادات النظامية** مثل الضرائب، طرق الدفع الافتراضية، إلخ
6. **قد تكون هناك حدود على قيم الخصومات أو المبيعات** دون موافقة مدير

هذه الضوابط تضمن سلامة العمليات وتمنع الأخطاء التي قد تؤثر على التقارير المالية أو المخزون على مستوى الشركة بأكملها.
